<systematic_approach>
Follow this step-by-step process. If a required tool is absent, skip that step and record a note in the deliverable.

**Step 1 — Cloud Provider Detection**
Read `target_profile_deliverable.md` (if present) and the previous SSL/TLS deliverable. Identify which cloud provider(s) are in use: AWS, GCP, Azure, or none. If none can be determined, proceed with passive repository analysis only and document as "Unknown / No Cloud Detected".

**Step 2 — Repository Cloud Config Discovery**
Search the repository for cloud configuration files and credentials:

```bash
# Locate IaC and cloud config files
find {{REPO_PATH}} -maxdepth 5 \( -name "*.tf" -o -name "*.tfvars" -o -name "serverless.yml" -o -name "samconfig.toml" -o -name ".aws/credentials" -o -name "*.yaml" \) | xargs grep -l "aws\|gcp\|azure\|bucket\|iam\|role\|policy" 2>/dev/null | head -20

# Detect hardcoded cloud credentials and ARNs
grep -r "AKIA\|ASIA\|aws_access_key\|aws_secret\|gcp_credentials\|azure_client" {{REPO_PATH}} --include="*.env*" --include="*.yaml" --include="*.json" --include="*.tf" 2>/dev/null | grep -v ".git" | head -20

# Find S3 bucket references in source code
grep -r "s3://" {{REPO_PATH}} --include="*.tf" --include="*.yaml" --include="*.json" --include="*.js" --include="*.ts" 2>/dev/null | grep -v ".git" | head -20
```

If no relevant files are found, document "No cloud configuration files detected" and proceed to Step 5.

**Step 3 — Active Cloud Scanning (Credential-Dependent)**
Only execute if cloud credentials are available in the environment. If tools are absent, skip with a note.

```bash
# Prowler — AWS misconfiguration checks (skip if 'prowler' not found or no AWS creds)
prowler aws --checks s3_bucket_public_access_block s3_bucket_policy_public_write_access ec2_securitygroup_allow_wide_open_access iam_root_credentials_use iam_user_mfa_enabled_console_access --output-formats json --output-directory {{REPO_PATH}}/.vanguard/scratchpad/ 2>&1 | head -100

# ScoutSuite — multi-cloud audit (skip if 'scout' not found or no cloud creds)
scout aws --no-browser --report-dir {{REPO_PATH}}/.vanguard/scratchpad/scoutsuite/ 2>&1 | head -50
```

**Step 4 — Passive Public Bucket Enumeration**
For any bucket names or storage references found in Step 2, perform passive HTTP checks:

```bash
# Test S3 bucket public access (replace BUCKET_NAME with discovered names)
curl -s -o /dev/null -w "%{http_code}" https://BUCKET_NAME.s3.amazonaws.com/ 2>/dev/null

# Check for public GCS buckets
curl -s -o /dev/null -w "%{http_code}" https://storage.googleapis.com/BUCKET_NAME/ 2>/dev/null
```

**Step 5 — IaC Security Review**
Use Task agents to analyse any Terraform, CloudFormation, Pulumi, or Serverless Framework files found:
- IAM policies with `*` (wildcard) actions or resources
- S3 buckets missing `block_public_acls`, `block_public_policy`, `ignore_public_acls`, `restrict_public_buckets`
- Security groups with `0.0.0.0/0` ingress on sensitive ports
- Lambda functions with overly broad execution roles
- Secrets or environment variables embedded directly in IaC

**Step 6 — Metadata Endpoint Exposure**
Check whether the target application proxies or reflects AWS/GCP metadata endpoint responses:

```bash
# Attempt metadata endpoint access via the target (SSRF indicator — passive check only)
curl -s --max-time 5 "{{WEB_URL}}/latest/meta-data/" 2>/dev/null | head -20
curl -s --max-time 5 "{{WEB_URL}}/?url=http://169.254.169.254/latest/meta-data/" 2>/dev/null | head -20
```
</systematic_approach>
