<systematic_approach>
Follow this step-by-step methodology. Use `vanguardFetch` for all HTTP requests.

**Step 1 — Fetch Homepage and Baseline Headers**
```bash
vanguard-fetch '{"url":"{{TARGET_URL}}","ua_bundle":"chrome120","rate_limit_rps":5}'
```
Record all response headers. Note: Server, X-Powered-By, Via, CF-Ray (WAF indicators).

**Step 2 — Security Headers Audit**
Check each of the following on the homepage and on `/api/` or `/api/v1/` if it exists:

| Header | Expected Value | Missing = Risk |
|---|---|---|
| Strict-Transport-Security | max-age≥31536000; includeSubDomains | High |
| Content-Security-Policy | present and restrictive | Medium-High |
| X-Frame-Options | DENY or SAMEORIGIN | Medium |
| X-Content-Type-Options | nosniff | Medium |
| Referrer-Policy | no-referrer or strict-origin | Low |
| Permissions-Policy | present | Low |
| Cross-Origin-Opener-Policy | same-origin | Low |

Score each: **Present** / **Missing** / **Misconfigured** (present but wrong value).

**Step 3 — CORS Configuration**
Test for wildcard or overly-permissive CORS:
```bash
# Test with a foreign origin
vanguard-fetch '{"url":"{{TARGET_URL}}/api/","ua_bundle":"chrome120","headers":{"Origin":"https://evil.com"}}'
```
Check response for `Access-Control-Allow-Origin: *` or `Access-Control-Allow-Origin: https://evil.com`.

Also test authenticated endpoints if the app has obvious API paths:
```bash
vanguard-fetch '{"url":"{{TARGET_URL}}/api/user","ua_bundle":"chrome120","headers":{"Origin":"https://evil.com"}}'
```

**Step 4 — Cookie Security Flags**
From the homepage response (and any login redirect), examine all `Set-Cookie` headers:
- `HttpOnly` flag — missing = XSS can steal cookie
- `Secure` flag — missing = cookie sent over HTTP
- `SameSite` — None without Secure = CSRF exposure; Lax or Strict preferred
- Session cookie names (PHPSESSID, JSESSIONID, .ASPXAUTH, laravel_session, connect.sid) — reveals framework

**Step 5 — HTTPS Enforcement**
```bash
# Test HTTP→HTTPS redirect
vanguard-fetch '{"url":"http://{{TARGET_DOMAIN}}","ua_bundle":"chrome120","rate_limit_rps":2}'
```
Check: does HTTP redirect to HTTPS? Is HSTS set? Is HSTS preloaded?

**Step 6 — Exposed Sensitive Endpoints**
Probe these paths (one at a time, respect rate limit):
```
/.env                    /config.php              /.git/config
/phpinfo.php             /adminer.php             /wp-admin/
/admin                   /admin/login             /administrator/
/actuator                /actuator/env            /actuator/heapdump
/actuator/beans          /debug                   /console
/api/swagger.json        /api/openapi.json        /swagger-ui.html
/graphql                 /__graphql               /api/graphql
/.well-known/security.txt
```
For each: record status code, Content-Type, and first 200 chars of body.
Flag anything returning 200 with sensitive content.

**Step 7 — Debug Mode & Error Leakage**
Trigger deliberate 404 and 500 errors to check for stack traces:
```bash
vanguard-fetch '{"url":"{{TARGET_URL}}/nonexistent-path-zz9pza32","ua_bundle":"chrome120"}'
vanguard-fetch '{"url":"{{TARGET_URL}}/api/nonexistent-zz9pza32","ua_bundle":"chrome120"}'
```
Check if response contains: framework names, file paths, line numbers, database connection strings, or internal IP addresses.

**Step 8 — Information Disclosure Headers**
Note any headers that reveal internal infrastructure:
- `Server: Apache/2.4.51` — version disclosure
- `X-Powered-By: PHP/8.1.2` — version disclosure
- `X-AspNet-Version:` — .NET version
- `X-Generator:` — CMS/framework
- `X-Drupal-Cache:` — CMS disclosure
</systematic_approach>
