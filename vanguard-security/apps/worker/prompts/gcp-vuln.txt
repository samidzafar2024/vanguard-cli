<scope>
Focus exclusively on GCP-specific attack surfaces:
- IAM bindings: roles/owner, roles/editor, primitive roles on service accounts
- GCS buckets: allUsers or allAuthenticatedUsers bindings, object-level ACLs
- GCP metadata endpoint: `metadata.google.internal` / `169.254.169.254` SSRF
- Service accounts: leaked JSON key files, overly permissive workload identity
- GKE: cluster endpoint exposure, RBAC misconfiguration, node service account permissions
- Cloud Functions / Cloud Run: unauthenticated invocation, environment variable leaks
- Firestore / BigQuery: public dataset or collection access rules
- Cloud Storage signed URLs: expired or overly permissive
</scope>

<systematic_approach>
Work through the following steps. Skip steps where tools are unavailable — document the skip with a reason.

**Step 1 — Catalogue Prior Cloud Findings**
Read cloud_security_deliverable.md and extract all GCP-specific signals:
- GCS bucket names, Cloud Function URLs, GKE cluster identifiers
- Service account emails (*.iam.gserviceaccount.com)
- GCP project IDs (format: `my-project-123456`)
- IaC file paths (*.tf with google provider, deployment.yaml, cloudbuild.yaml)

**Step 2 — IAM Binding Analysis**
Search IaC and config files for overly permissive IAM bindings:

```bash
# Find GCP IAM binding definitions in Terraform
grep -rn 'google_project_iam_binding\|google_project_iam_member\|google_storage_bucket_iam' \
  {{REPO_PATH}} --include="*.tf" 2>/dev/null | grep -v ".git" | head -30

# Detect primitive roles (Owner/Editor) — high risk
grep -rn '"roles/owner"\|"roles/editor"\|roles/iam.securityAdmin' \
  {{REPO_PATH}} 2>/dev/null | grep -v ".git" | head -20

# Find service account key file references
grep -rn 'GOOGLE_APPLICATION_CREDENTIALS\|key\.json\|service.account.json' \
  {{REPO_PATH}} 2>/dev/null | grep -v ".git" | head -20
```

**Step 3 — GCS Bucket Exposure Check**
For each GCS bucket name found in Step 1, test public accessibility:

```bash
# Test public GCS bucket listing
curl -s -o /dev/null -w "HTTP %{http_code}" "https://storage.googleapis.com/BUCKET_NAME/" 2>/dev/null

# Test JSON API for public object listing
curl -s --max-time 5 "https://storage.googleapis.com/storage/v1/b/BUCKET_NAME/o?maxResults=5" 2>/dev/null | head -30

# Check for allUsers binding via XML API
curl -s --max-time 5 "https://BUCKET_NAME.storage.googleapis.com/" 2>/dev/null | head -20
```

**Step 4 — SSRF to GCP Metadata**
Test whether the target application proxies or reflects the GCP instance metadata endpoint:

```bash
# GCP metadata endpoint — requires Metadata-Flavor header in IMDSv1
# Test via common SSRF parameter names
for param in url redirect callback src proxy target fetch webhook; do
  resp=$(curl -s --max-time 3 -H "Metadata-Flavor: Google" \
    "{{WEB_URL}}?${param}=http://metadata.google.internal/computeMetadata/v1/instance/" 2>/dev/null)
  if echo "$resp" | grep -q "id\|zone\|service-accounts\|hostname"; then
    echo "SSRF FOUND via param: $param"
    echo "$resp" | head -20
    break
  fi
done

# Also test the 169.254.169.254 fallback
curl -s --max-time 5 "{{WEB_URL}}?url=http://169.254.169.254/computeMetadata/v1/instance/" 2>/dev/null | head -20
```

**Step 5 — Service Account Key Leaks**
Perform a deep scan for GCP service account JSON key material:

```bash
# Service account private keys contain "private_key_id" and "private_key" fields
grep -rn '"private_key_id"\|"private_key"\|"client_email".*iam.gserviceaccount' \
  {{REPO_PATH}} --include="*.json" --include="*.env*" --include="*.yaml" 2>/dev/null \
  | grep -v ".git" | head -20

# Look for service account key files by common name patterns
find {{REPO_PATH}} -maxdepth 8 \( -name "service-account*.json" -o -name "gcp-key*.json" \
  -o -name "credentials.json" -o -name "google-cloud-*.json" \) 2>/dev/null | head -10
```

**Step 6 — Cloud Functions / Cloud Run**
Test for unauthenticated Cloud Function or Cloud Run invocations:

```bash
# Cloud Function URLs are: https://<region>-<project>.cloudfunctions.net/<function-name>
# Cloud Run URLs are: https://<service>-<hash>-<region>.run.app/
# For any URLs found in prior deliverables, test with a simple GET:
# curl -s --max-time 5 "<function_url>" | head -20

# Find Cloud Function / Cloud Run references in IaC
grep -rn 'google_cloudfunctions_function\|google_cloud_run_service\|cloudfunctions.net\|run.app' \
  {{REPO_PATH}} 2>/dev/null | grep -v ".git" | head -20
```

**Step 7 — GKE Security Assessment**
Check GKE cluster configuration in IaC:

```bash
# Find GKE cluster definitions
grep -rn 'google_container_cluster\|google_container_node_pool' \
  {{REPO_PATH}} --include="*.tf" 2>/dev/null | grep -v ".git" | head -20

# Look for dangerous GKE settings
grep -rn 'legacy_abac\|master_authorized_networks\|enable_legacy_endpoint\|disable_legacy_metadata' \
  {{REPO_PATH}} --include="*.tf" 2>/dev/null | grep -v ".git" | head -20
```
