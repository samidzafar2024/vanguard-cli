<calibration_methodology>

**Step 1 — Probe 1: Standard homepage request**
Use current WAF bypass settings from brain hints:
```bash
vanguard-fetch '{"url":"{{TARGET_URL}}","ua_bundle":"<from hints>","rate_limit_rps":<from hints>}'
```
Record: status code, response time (ms), Content-Length.

Wait 3 seconds.

**Step 2 — Probe 2: API endpoint request**
If an API path was identified in previous deliverables, probe it:
```bash
vanguard-fetch '{"url":"{{TARGET_URL}}/api/","ua_bundle":"<from hints>","rate_limit_rps":<from hints>}'
```
If no API path known, use `{{TARGET_URL}}/robots.txt`.
Record: status code, response time, any WAF challenge indicators.

Wait 3 seconds.

**Step 3 — Probe 3: Slightly suspicious but legal request**
```bash
vanguard-fetch '{"url":"{{TARGET_URL}}/login","ua_bundle":"<from hints>","rate_limit_rps":<from hints>}'
```
Record: status code, any CAPTCHA, Cloudflare challenge, 429 rate-limit, or 403 block.

**Step 4 — Classify OPSEC Status**

Evaluate all 3 probes:

| Status | Criteria |
|---|---|
| **OK** | All 3 probes returned expected status codes (200, 301, 302, 404). No WAF blocks. |
| **WARN** | 1-2 probes returned 429 or unusual responses. WAF may be adapting. |
| **BLOCKED** | 2+ probes returned 403/429/WAF challenge page. Active blocking detected. |

**Step 5 — Calculate Adjusted Rate**

- If OK: keep current rate. No adjustment needed.
- If WARN: reduce rate by 50%. Change ua_bundle to next in rotation (chrome120 → firefox117 → safari17).
- If BLOCKED: reduce rate to 0.5 RPS (1 request every 2 seconds). Add 10-second delay between agents. Recommend operator review before continuing.
</calibration_methodology>
