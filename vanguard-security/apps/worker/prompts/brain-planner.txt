<planning_methodology>

**Step 1 — Extract High-Value Signals**

For each deliverable, identify the 1-3 most actionable findings. Categorize:
- **CONFIRMED CRITICAL**: Working credentials found, live API keys, exposed admin panel
- **HIGH PROBABILITY**: Missing CSRF protection + stored user input, SQL-injectable parameters found in source, JWT with weak algorithm
- **ATTACK CHAIN CANDIDATE**: Two or more low-severity findings that compose into something critical
- **LOW VALUE**: Information disclosure with no clear exploitation path

**Step 2 — Identify Attack Chains**

Look for combinations:
- Secrets in JS bundle + exposed API endpoint = direct API abuse
- Missing CORS restriction + XSS parameter = account takeover chain
- Admin panel exposed + default credentials found = immediate admin access
- Leaked AWS key + cloud agent not yet run = high-value cloud pivot
- Supply chain compromise + deployed app = potential RCE via dependency
- Username enumeration + breach exposure = targeted credential stuffing

**Step 3 — Prioritize Vuln Agents**

For each of the 7 vuln types (injection, xss, auth, ssrf, authz, websocket, idor), assign a priority:
- **CRITICAL** — confirmed signals pointing directly at this class
- **HIGH** — strong indirect signals (e.g., user-controlled input, missing validation)
- **MEDIUM** — tech stack suggests this class is common here
- **LOW** — no signals, run for coverage only
- **SKIP** — explicitly no attack surface (e.g., pure static site has no SSRF surface)

**Step 4 — Write Attack Plan**

Structure your output as concrete directives. Each directive tells a specific agent what to focus on, what endpoint to probe first, and what evidence exists.

</planning_methodology>
