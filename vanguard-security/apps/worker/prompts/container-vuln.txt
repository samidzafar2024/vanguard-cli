<systematic_approach>
Follow this step-by-step process. If a required tool is absent, skip that step and record a note in the deliverable.

**Step 1 — Container Infrastructure Discovery**
Locate all container-related files in the repository:

```bash
# Find Dockerfiles
find {{REPO_PATH}} -name "Dockerfile*" -not -path "*/node_modules/*" -not -path "*/.git/*" | head -20

# Find Docker Compose files
find {{REPO_PATH}} -name "docker-compose*.yml" -o -name "docker-compose*.yaml" | grep -v ".git" | head -10

# Find Kubernetes manifests
find {{REPO_PATH}} -name "*.yaml" -path "*/k8s/*" -o -name "*.yaml" -path "*/kubernetes/*" -o -name "*.yaml" -path "*/manifests/*" 2>/dev/null | grep -v ".git" | head -20

# Find Helm charts
find {{REPO_PATH}} -name "Chart.yaml" | head -10
```

If no container files are found, document "No container infrastructure detected" and complete Section 7 (Not Applicable) of the deliverable.

**Step 2 — Trivy Image Scanning (skip if 'trivy' not found)**
For each Dockerfile discovered, extract the base image and scan for CVEs:

```bash
find {{REPO_PATH}} -name "Dockerfile" -not -path "*/node_modules/*" | while read df; do
  IMAGE=$(grep "^FROM" "$df" | tail -1 | awk '{print $2}')
  echo "Scanning image: $IMAGE from $df"
  trivy image "$IMAGE" --severity HIGH,CRITICAL --format json \
    --output {{REPO_PATH}}/.vanguard/scratchpad/trivy_image_$(basename $(dirname $df)).json 2>&1 | head -50
done
```

**Step 3 — Trivy Config Scanning (skip if 'trivy' not found)**
Scan IaC and container configs for misconfigurations:

```bash
# JSON output for structured parsing
trivy config {{REPO_PATH}} --format json \
  --output {{REPO_PATH}}/.vanguard/scratchpad/trivy_config.json 2>&1

# Human-readable table for immediate review
trivy config {{REPO_PATH}} --format table 2>&1 | head -80
```

**Step 4 — Checkov IaC Scanning (skip if 'checkov' not found)**
Run policy checks across all supported frameworks:

```bash
# Full scan with JSON output
checkov -d {{REPO_PATH}} \
  --framework terraform,kubernetes,dockerfile,docker_compose \
  --output json > {{REPO_PATH}}/.vanguard/scratchpad/checkov_results.json 2>&1

# Dockerfile HIGH checks for quick review
checkov -d {{REPO_PATH}} --framework dockerfile --check HIGH 2>&1 | head -60
```

**Step 5 — Dockerfile Manual Review**
Use Task agents to analyse each Dockerfile for:
- Running processes as root (missing `USER` directive)
- Use of `latest` tag for base images (no pinned digest)
- Secrets or tokens in `ENV`, `ARG`, or `RUN` instructions
- Unnecessary package installation with `--no-install-recommends` missing
- Multi-stage build misuse exposing build secrets in final image
- `ADD` used instead of `COPY` (potential remote URL fetch)
- `COPY . .` copying sensitive files (`.env`, credentials) into image

**Step 6 — Docker Compose Security Review**
Analyse each Docker Compose file for high-risk configurations:

```bash
find {{REPO_PATH}} -name "docker-compose*.yml" -o -name "docker-compose*.yaml" | while read dc; do
  echo "=== $dc ==="
  grep -E "privileged|ports|volumes|environment|\.env|cap_add|security_opt|network_mode|pid" "$dc" 2>/dev/null
done
```

Flag: `privileged: true`, host network mode, host PID namespace, sensitive host path mounts (`/var/run/docker.sock`, `/etc`, `/root`), hardcoded secrets in `environment:` blocks.

**Step 7 — Kubernetes Manifest Review**
For any Kubernetes YAML files found, use Task agents to check:
- `securityContext.privileged: true` on containers or pods
- `hostPID: true`, `hostNetwork: true`, `hostIPC: true` on pod specs
- Missing `securityContext.runAsNonRoot: true`
- Missing `securityContext.readOnlyRootFilesystem: true`
- Containers with `allowPrivilegeEscalation: true` or missing the field
- Unrestricted `capabilities.add` (especially `SYS_ADMIN`, `NET_ADMIN`, `ALL`)
- Services of type `LoadBalancer` or `NodePort` with no network policy
- Ingress resources missing TLS configuration
- Secrets mounted as environment variables rather than volume mounts
- Default service account tokens auto-mounted without need (`automountServiceAccountToken: true`)

**Step 8 — kube-bench Assessment (skip if 'kube-bench' not found or no live cluster)**
```bash
# Static manifest check only — no live cluster connection
find {{REPO_PATH}} -name "*.yaml" \( -path "*/k8s/*" -o -path "*/kubernetes/*" \) | head -5
```
