<systematic_approach>

**Step 1 — Load Prior Intelligence**
Read hardening_auditor_deliverable.md to extract:
- Login endpoints (e.g. `/admin/login`, `/wp-admin/`, `/actuator`)
- Framework hints (determines which defaults to try)

Read osint_recon_deliverable.md to extract:
- Email pattern (e.g. `firstname.lastname@domain.com`)
- Known breach indicators

**Step 2 — Default Credential Testing**
For each discovered admin/login endpoint, attempt the following defaults ONLY (3 attempts max total per endpoint):

Common defaults by framework:
| Framework | Default Username | Default Password |
|---|---|---|
| WordPress | admin | admin, password, 123456 |
| Laravel | admin@example.com | password |
| Django Admin | admin | admin |
| Tomcat Manager | admin, tomcat | admin, tomcat, s3cret |
| phpMyAdmin | root, admin | (empty), root, admin |
| Grafana | admin | admin |
| Jenkins | admin | admin, password |
| Portainer | admin | admin, password |
| GitLab | root | 5iveL!fe (old default) |

Use vanguardFetch with POST for each attempt:
```bash
vanguard-fetch '{"url":"{{TARGET_URL}}/admin/login","method":"POST","body":"username=admin&password=admin","ua_bundle":"chrome120","rate_limit_rps":0.2}'
```

Wait 5 seconds between each attempt. Stop after 3 failures on any single endpoint.

**Step 3 — HIBP Domain Breach Check**
```bash
# Check if domain has known breaches (no API key needed for domain check)
curl -s "https://haveibeenpwned.com/api/v3/breachesforaccount/{{TARGET_DOMAIN}}" \
  -H "User-Agent: VanguardSecurityAudit/1.0 (authorized-pentest)" 2>/dev/null | head -200

# Also check via public search (passive)
# Search: site:haveibeenpwned.com "{{TARGET_DOMAIN}}"
```

**Step 4 — Exposed Credential Files (from Hardening Audit)**
If the hardening audit found any of these returning 200, attempt to read them:
- `/.env` — may contain DB_PASSWORD, API keys
- `/config.php`, `/.htpasswd`
- `/actuator/env` — may contain database URLs with credentials

Extract any credential-shaped strings (passwords, API keys, connection strings).

**Step 5 — Rate-Limited Username Enumeration (if login form exists)**
On the primary login form only, test whether the app differentiates between "invalid username" and "invalid password" responses:
```bash
# Test with non-existent username
vanguard-fetch '{"url":"{{TARGET_URL}}/login","method":"POST","body":"email=nonexistent_user_zz9pza32@{{TARGET_DOMAIN}}&password=TestPass123","ua_bundle":"chrome120","rate_limit_rps":0.2}'

# Test with likely-real admin email pattern
vanguard-fetch '{"url":"{{TARGET_URL}}/login","method":"POST","body":"email=admin@{{TARGET_DOMAIN}}&password=TestPass123","ua_bundle":"chrome120","rate_limit_rps":0.2}'
```

Compare responses: if they differ (different message, different redirect, different status), user enumeration is possible — document it.
</systematic_approach>
