<scope>
Focus on client-side attack surfaces:
- **CSP bypass**: missing directives, unsafe-inline, unsafe-eval, JSONP endpoints that bypass script-src
- **postMessage vulnerabilities**: missing origin validation, wildcard targetOrigin ('*'), deserialization of untrusted messages
- **Service Worker hijacking**: scope misconfiguration, unprotected SW registration endpoints, cache poisoning
- **CORS misconfiguration**: credentials: true with wildcard or origin reflection, private network access
- **prototype pollution**: client-side JavaScript merging of user-controlled objects
- **DOM clobbering**: named form elements overwriting globals, anchor elements polluting getElementById
- **Subresource Integrity (SRI)**: third-party scripts loaded without integrity attributes
- **Open redirects leading to XSS**: redirect to javascript: scheme or data: URLs
- **iframe sandbox bypass**: missing allow-scripts/allow-same-origin combinations
</scope>

<systematic_approach>
**Step 1 — CSP Analysis**
Retrieve the live CSP header and parse it for weaknesses:

```bash
curl -s -I "{{WEB_URL}}" 2>/dev/null | grep -i "content-security-policy"

# Check for common bypasses:
# - unsafe-inline or unsafe-eval in script-src
# - Missing default-src fallback
# - JSONP endpoints in script-src allowlist (look for *.googleapis.com, *.cloudflare.com)
# - base-uri not set (allows base tag injection)
# - form-action not set (allows form hijacking)
```

**Step 2 — CORS Configuration**
Test CORS policy for credential-bearing cross-origin requests:

```bash
# Test if credentials are reflected back
curl -s -I "{{WEB_URL}}/api/" \
  -H "Origin: https://attacker.example.com" \
  -H "Cookie: session=test" 2>/dev/null | grep -i "access-control"

# Test null origin
curl -s -I "{{WEB_URL}}/api/" \
  -H "Origin: null" 2>/dev/null | grep -i "access-control"
```

**Step 3 — postMessage Analysis**
Search the JavaScript source for postMessage handlers without origin checks:

```bash
# Download and search main JS bundles from the recon deliverable
# Look for addEventListener('message') without origin validation
curl -s "{{WEB_URL}}" 2>/dev/null | grep -o 'src="[^"]*\.js[^"]*"' | head -10
```

**Step 4 — Service Worker Detection**
Check for service worker registrations and assess scope:

```bash
# Check for service worker registration
curl -s "{{WEB_URL}}" 2>/dev/null | grep -i "serviceWorker\|navigator\.serviceWorker" | head -5

# Try to fetch the service worker script directly
curl -s "{{WEB_URL}}/sw.js" -o /dev/null -w "%{http_code}" 2>/dev/null
curl -s "{{WEB_URL}}/service-worker.js" -o /dev/null -w "%{http_code}" 2>/dev/null
```

**Step 5 — Third-party Script SRI Check**
Check whether third-party scripts are loaded without Subresource Integrity:

```bash
curl -s "{{WEB_URL}}" 2>/dev/null | grep -i '<script' | grep -v 'integrity=' | grep 'http' | head -10
```

**Step 6 — Prototype Pollution & DOM Clobbering**
Search source for merge/extend patterns and named DOM elements:

```bash
# Look for dangerous object merge patterns in JS
# These patterns indicate potential prototype pollution vectors
grep -r "Object\.assign\|_.merge\|_.extend\|jQuery\.extend\|deepMerge" \
  {{REPO_PATH}} --include="*.js" --include="*.ts" 2>/dev/null | grep -v ".git\|node_modules" | head -20
```
</systematic_approach>
