<methodology>
**IDOR Analysis Process (per endpoint):**

**Step 1 — Object ID Parameter Identification**
From recon Section 4, list all endpoints with path/query parameters that contain IDs:
- `/api/users/{user_id}` — user_id
- `/api/orders/{order_id}` — order_id
- `/api/files/{file_id}` — file_id
- `/api/reports/{report_id}` — report_id

**Step 2 — Ownership Check Trace (via Task Agent)**
For each endpoint, launch a Task agent:
```
"Trace the ownership validation for endpoint [METHOD] [PATH]. Starting from the route handler, trace:
1. How is the requesting user's identity extracted (JWT claim, session, etc.)?
2. How is the target object (ID={param}) loaded from the database?
3. Is there a comparison between the requesting user's ID and the object's owner_id?
4. If yes, can the check be bypassed (type confusion, integer vs string, NULL ownership)?
5. If no ownership check exists, confirm the endpoint is IDOR-vulnerable.
Provide file paths and line numbers for each step."
```

**Step 3 — ID Type Analysis**
Determine what type of IDs are used:
- **Sequential integers** (e.g., 1, 2, 3) — trivially enumerable
- **UUIDs** — not easily guessable but can be leaked from other endpoints
- **Slugs** (e.g., `/api/reports/q4-2024`) — guessable if predictable patterns

For UUIDs: check if any endpoint leaks other users' IDs (e.g., admin listing endpoint, activity logs, shared resources).

**Step 4 — Multi-Tenant Isolation**
If the app has organisations/teams:
- Can a user in org A access resources from org B by changing the org_id?
- Are tenant IDs in URLs or only in JWT claims?

**Step 5 — HTTP Method Variation**
For each vulnerable-looking endpoint, test all HTTP methods:
- GET /api/resources/OTHER_ID — read IDOR
- PUT /api/resources/OTHER_ID — write IDOR (more severe)
- DELETE /api/resources/OTHER_ID — delete IDOR (most severe)
- PATCH /api/resources/OTHER_ID — partial update IDOR

**Step 6 — Indirect IDOR via Associations**
Some IDORs are indirect — you access your own object but reference another user's object within it:
- `POST /api/comments` with `{"post_id": ANOTHER_USERS_PRIVATE_POST_ID}`
- `POST /api/transfers` with `{"from_account_id": VICTIM_ID, "amount": 100}`
