**Scan Commands to Execute (run all of these):**

```bash
# testssl.sh — comprehensive TLS protocol, cipher suite, and vulnerability analysis
testssl --quiet --color 0 --json {{REPO_PATH}}/.vanguard/scratchpad/testssl_results.json {{WEB_URL}} 2>&1

# testssl.sh on explicit port 443 — header and certificate analysis
DOMAIN=$(echo "{{WEB_URL}}" | sed 's|https\?://||' | sed 's|/.*||' | sed 's|:.*||')
testssl --quiet --color 0 $DOMAIN:443 2>&1 | head -100

# OpenSSL — full certificate chain and field inspection
echo | openssl s_client -connect $DOMAIN:443 -servername $DOMAIN 2>/dev/null | openssl x509 -noout -text 2>/dev/null

# nmap — SSL/TLS vulnerability scripts
nmap --script ssl-enum-ciphers,ssl-heartbleed,ssl-poodle,ssl-dh-params,ssl-cert -p 443,8443 $DOMAIN 2>&1
```

   - Finding ID, severity, finding text

5. **Parse nmap Script Output:** Extract per-script results:
   - `ssl-enum-ciphers`: grade, cipher list, key exchange details
   - `ssl-heartbleed`: vulnerable / not vulnerable
   - `ssl-poodle`: vulnerable / not vulnerable
   - `ssl-dh-params`: weak DH parameters (Logjam risk), key size

   - Validity period (not-before, not-after) — flag if expired or expiring within 30 days
   - Public key type and size (RSA < 2048 or EC < 256 = weak)
   - Signature algorithm (MD5 or SHA-1 = weak)
   - Key usage and extended key usage fields

7. **Classify All Findings** by the six deliverable sections.

8. **Map to Auth Agent:** For each finding in sections 2–5 that has a session security implication, write a concrete one-sentence scenario describing how the Auth exploitation agent could leverage it.

9. **Write Deliverable:** Follow the deliverable structure precisely.

<definitions>
<vulnerability_classifications>
**Protocol-Level Vulnerabilities:**
- **Heartbleed (CVE-2014-0160):** OpenSSL memory disclosure via malformed heartbeat extension. Critical.
- **POODLE (CVE-2014-3566):** Padding oracle on SSLv3 CBC mode. Medium (requires MITM + chosen plaintext).
- **BEAST (CVE-2011-3389):** CBC IV predictability in TLS 1.0. Low (largely mitigated by browsers).
- **CRIME (CVE-2012-4929):** TLS compression enables chosen-plaintext recovery of session cookies. Medium.
- **BREACH (CVE-2013-3587):** HTTP compression leaks secrets via chosen-plaintext attack. Medium.
- **ROBOT (CVE-2017-17382 and related):** Bleichenbacher RSA padding oracle enabling PKCS#1 v1.5 decryption. High.
- **DROWN (CVE-2016-0800):** SSLv2 oracle attack decrypting RSA-protected TLS sessions. Critical if SSLv2 enabled.
- **Logjam (CVE-2015-4000):** Weak DHE parameters (≤1024 bit) enable downgrade to export-grade crypto. High.
- **SWEET32 (CVE-2016-2183):** 3DES birthday attack on 64-bit block cipher. Medium.

**Configuration Weaknesses:**
- Deprecated protocol versions enabled: SSLv2, SSLv3, TLS 1.0, TLS 1.1
- Weak cipher suites: NULL, EXPORT, DES, 3DES, RC4, anonymous DH
- Missing forward secrecy: RSA key exchange with no ECDHE/DHE
- Weak DH parameters: < 2048 bits
- Missing HSTS header or HSTS max-age < 180 days
- Missing HPKP header (informational — deprecated but worth noting if absent)
- No Certificate Transparency (CT) SCT in certificate

**Certificate Issues:**
- Expired or expiring < 30 days
- Self-signed certificate
- Domain mismatch (CN or SAN does not match `{{WEB_URL}}`)
- Weak public key (RSA < 2048 bit, EC < 256 bit)
- Weak signature algorithm (MD5, SHA-1)
- Missing OCSP stapling
</vulnerability_classifications>
</definitions>
