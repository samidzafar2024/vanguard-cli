<systematic_approach>
For each unique confirmed finding:

**1. Root Cause Analysis**
Identify the underlying code pattern or configuration error. Is it:
- Missing input validation at the boundary?
- Broken authorization check (IDOR, privilege escalation)?
- Unsafe deserialization or template rendering?
- Missing security header or cookie flag?
- Overprivileged IAM role or exposed cloud resource?
- Hardcoded credential or secret?

**2. Fix Generation**
Write the specific fix. Use the tech stack from `target_profile_deliverable.md` to tailor the fix to the detected language/framework:

- **Node.js/Express SQL injection**: parameterized queries with `pg` or `mysql2`
- **Python/Django SQL injection**: Django ORM `filter()` instead of raw SQL
- **JWT issues**: signature verification, algorithm pinning, expiry validation
- **XSS**: DOMPurify sanitization, CSP header, innerHTML → textContent
- **SSRF**: allowlist of permitted URLs, block 169.254.x.x and 10.x.x.x
- **Missing security headers**: specific `helmet.js` or Django `SecurityMiddleware` configuration
- **IDOR**: ownership check before data access
- **Cloud IAM**: least-privilege policy with specific resource ARNs

**3. Re-test Procedure**
Write the exact curl command or test step that verifies the fix is effective:
```bash
# Re-test for SQL injection fix:
curl -s "{{WEB_URL}}/api/endpoint?param=1' OR '1'='1" | grep -c "error\|syntax\|SQL"
# Expected: 0 (no SQL error in response)
```

**4. Priority Ordering**
Order by:
1. Critical: Remote code execution, authentication bypass, full data breach
2. High: Privilege escalation, sensitive data exposure, SSRF with internal access
3. Medium: XSS, IDOR for non-sensitive data, missing security headers
4. Low: Information disclosure, weak cipher suites, non-critical misconfigurations
</systematic_approach>

## Step 2: Create GitHub PR (if GITHUB_TOKEN is available)

If `$GITHUB_TOKEN` is set in the environment AND the repository at `{{REPO_PATH}}` is a git repository with a GitHub remote, create a PR with the fixes:

```bash
# Check if gh is authenticated
if [ -n "$GITHUB_TOKEN" ] && gh auth status 2>/dev/null; then
  cd {{REPO_PATH}}

  # Create a new branch
  BRANCH="vanguard-fixes-$(date +%Y%m%d-%H%M%S)"
  git checkout -b "$BRANCH" 2>/dev/null || true

  # Stage any modified files
  git add -A 2>/dev/null || true

  # Commit if there are changes
  git diff --staged --quiet 2>/dev/null || git commit -m "fix: Vanguard security remediation - $(date +%Y-%m-%d)" 2>/dev/null || true

  # Push and create PR
  git push -u origin "$BRANCH" 2>/dev/null && \
  gh pr create \
    --title "Security fixes from Vanguard scan ($(date +%Y-%m-%d))" \
    --body "$(cat {{REPO_PATH}}/.vanguard/deliverables/remediation_deliverable.md | head -100)" \
    --label "security" 2>/dev/null && \
  echo "PR_CREATED: success" || echo "PR_CREATED: failed (no remote or push failed)"
else
  echo "PR_CREATED: skipped (no GITHUB_TOKEN or gh not authenticated)"
fi
```

If the PR was created successfully (output contains `PR_CREATED: success`), append the PR URL to `.vanguard/deliverables/remediation_deliverable.md` under a `## GitHub PR` section. If PR creation was skipped or failed, continue without error.

Once successfully saved, announce "REMEDIATION PLAN COMPLETE" and stop.
