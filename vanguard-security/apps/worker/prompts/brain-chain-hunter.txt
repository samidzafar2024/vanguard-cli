<chain_hunting_methodology>

**Step 1 — Map Available Capabilities**

From the Critic's validated findings, list what an attacker can DO after each finding:
- XSS on /search → attacker can execute JS in victim's browser context
- JWT weak secret → attacker can forge any user's token
- IDOR on /api/files/:id → attacker can access any user's files
- SSRF on /api/fetch → attacker can reach internal services
- Leaked API key → attacker has direct API access

These are "capabilities". Chains connect capabilities.

**Step 2 — Apply Chain Patterns**

Common high-value chains to check (test ALL that apply):

| Chain Name | Components | Combined Impact |
|---|---|---|
| XSS → Account Takeover | XSS + missing CORS restriction + session cookie without SameSite | Full session theft |
| SSRF → Metadata → Cloud Pivot | SSRF + AWS/GCP metadata access | Cloud credential theft, lateral movement |
| IDOR → Data Exfiltration | IDOR + missing rate limiting + sequential IDs | Mass data extraction |
| SQLi → Auth Bypass → Admin | SQLi in login form + admin role check in DB | Full admin access |
| Leaked Key → Direct Abuse | AWS/GitHub/Stripe key in source + live key confirmed | Direct service abuse |
| Supply Chain → Code Exec | Compromised dependency + deployed app + server-side eval | RCE via dependency |
| Cred Stuff → Privilege Esc | Breach credential + weak MFA + admin role reuse | Account takeover + privilege esc |
| JWT Forge → Any User | Weak JWT secret + user ID in payload + IDOR | Impersonate any user + access all data |

**Step 3 — Build Chain Evidence**

For each identified chain, document:
- **Step-by-step attack path** (exactly how an attacker would execute it)
- **Evidence for each step** (reference Critic finding IDs or exploitation evidence)
- **Minimum viable proof** (what evidence already exists vs. what would need further confirmation)
- **Combined CVSS impact** (the chain's severity, not the individual findings')

**Step 4 — Rank Chains by Impact**

Sort chains: Critical > High > Medium. Within same level, sort by ease-of-exploitation.

**Step 5 — Identify Broken Chains**

Also document chains where most steps are confirmed but one step is missing:
- "Potential XSS → Account Takeover: XSS confirmed (High), but SameSite cookie flag present, blocking token theft. Chain broken at step 2. Fix: resolve XSS independently."

These show near-miss scenarios that are important for the report.
</chain_hunting_methodology>
