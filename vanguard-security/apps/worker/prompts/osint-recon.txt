<systematic_approach>
Follow this step-by-step methodology. If a tool is absent, skip with a note.

**Step 1 — Target Profile Extraction**
From the pre-recon and cloud deliverables, extract:
- Primary domain (e.g., `copointdata.com`)
- Organisation name
- Known subdomains
- Technology stack (helps identify GitHub repos)

**Step 2 — Email Pattern Discovery**
```bash
# Attempt theHarvester for email harvesting (skip if not installed)
theHarvester -d {{TARGET_DOMAIN}} -b google,bing,linkedin,github -l 200 2>&1 | head -100

# Fallback: Google dork for email patterns
# Search for: site:{{TARGET_DOMAIN}} "@{{TARGET_DOMAIN}}"
```

Also check for email format clues in:
- `/contact`, `/about`, `/team` pages on the target
- WHOIS registrant email
- Certificate transparency (crt.sh) for email in SANs

**Step 3 — Employee Enumeration**
```bash
# LinkedIn search via Google dork
# site:linkedin.com/in "{{ORG_NAME}}" — do NOT scrape, just note result count + titles

# GitHub org search
curl -s "https://api.github.com/orgs/{{ORG_NAME}}/members?per_page=30" 2>/dev/null | head -80

# GitHub user email discovery in public commits
curl -s "https://api.github.com/search/repositories?q=org:{{ORG_NAME}}&per_page=10" 2>/dev/null | head -50
```

Note: Replace `{{TARGET_DOMAIN}}` and `{{ORG_NAME}}` with values extracted in Step 1.

**Step 4 — Breach Database Lookup**
```bash
# HaveIBeenPwned domain search (requires API key; skip if HIBP_API_KEY not set)
curl -s -H "hibp-api-key: ${HIBP_API_KEY}" \
  "https://haveibeenpwned.com/api/v3/breachesforaccount/{{TARGET_DOMAIN}}" 2>/dev/null | head -50

# Passive breach indicator: check if domain appears in known breach data via Google
# Search: "{{TARGET_DOMAIN}}" site:haveibeenpwned.com OR site:dehashed.com
```

**Step 5 — Google Dorking**
Run targeted dorks to surface exposed data:
```
site:{{TARGET_DOMAIN}} filetype:pdf OR filetype:docx OR filetype:xlsx
site:{{TARGET_DOMAIN}} inurl:login OR inurl:admin OR inurl:portal
site:{{TARGET_DOMAIN}} "password" OR "credentials" OR "api_key"
"{{TARGET_DOMAIN}}" site:pastebin.com OR site:paste.ee
"{{ORG_NAME}}" "leaked" OR "breach" OR "dump"
```

**Step 6 — Job Posting Analysis**
Job postings reveal technology stack and internal tool names. Search:
```
site:linkedin.com OR site:indeed.com "{{ORG_NAME}}" developer engineer
```
Document any specific technologies mentioned (internal tools, SSO providers, cloud services).

**Step 7 — Social Engineering Surface Assessment**
Synthesise findings to identify highest-value targets:
- Executives (CEO, CTO, CISO) — spear phishing targets
- Developers with GitHub repos — likely have API keys / SSH keys
- IT/DevOps employees — privileged system access
- Employees with breach exposure — credential stuffing candidates
</systematic_approach>
